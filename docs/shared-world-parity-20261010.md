# Telegram PPA и Godot PPA: реализованное и оставшиеся этапы

10 октября 2026. Это изменения в отдельных ветках, а не подтверждение полной
совместимости или выпуска нового APK. Сборка APK и выпуск сервера были
приостановлены по просьбе владельца. Производственные флаги не включены.

## Основа

Один Phoenix аккаунт с привязанным Telegram персонажем, исходный realtime pid,
общий `ppa-global-v1`, существующие D1 `players`/`saves`/клановые таблицы.
Godot остаётся единственным рендерером своего мира. Telegram клиент сохраняет
свои текущие интерфейс, ассеты и обработчики боевого урона.

Проверенные базы: серверный main `2def905`, городской серверный PR #32
`d5c2cb7`, городской клиентский PR #31 `6a66bf5` поверх combat HUD `1475a9a`.
Новые команды накладываются на эти городские ветки. Их зависимые PR ещё
нужно интегрировать; наличие кода в ветке не означает наличие API в live.

## Что добавлено

**Кланы:** native GET `/api/game/clan/state`, POST `/api/game/clan/action`.
Персонаж определяется подписанной игровой сессией, а не ID из тела запроса.
Используются `state()` и `action()` из действующего `clan-online.js`.
Доступны создание, заявка, выход, принятие/отклонение заявки, исключение,
передача главы, полномочия участника, права склада none/all и распределение
существующих очков бонусов. Каталог, состав, журнал, прогресс и вещи кланового
склада отображаются из общих серверных таблиц. Перенос вещей пока выключен.
Изменение своего клана обновляет подписанное подключение уже подключённого
Godot клиента в городе; меню само не включает онлайн и не возобновляет
подключение вытесненного персонажа.

Исправлена общая ошибка: `mem()` возвращала clan_id/role/joined_at,
а `can()` искала полномочия по отсутствующему `telegram_id`. Выборка теперь
возвращает подлинный ID участника. Права, назначенные главой, работают в обоих
клиентах. Исходный обработчик кланов проверяется SHA с учётом этой выборки
и следующего переноса существующего ограничения выхода.

Запрет вступления/создания на 24 часа после выхода теперь хранится в общей
`clan_join_cooldowns`, учитывает прежний `clanJoinBlockedUntil` сохранения
и проверяется обоими серверными маршрутами. Он действует после выхода
из Telegram или Godot, переживает смену клиента и одноразовые клиентские
сбросы старых версий. Версия сейва, деньги, вещи и HP/MP при этом не меняются.
Godot показывает остаток ограничения и запрашивает свежее состояние.

**Обычный торговец:** native GET `/api/game/merchant/state`, POST
`/api/game/merchant/action`; общий typed обработчик также доступен через
Telegram POST `/api/merchant/state` и `/api/merchant/action` с прежней HMAC
авторизацией. Все 12 товаров, цены, валюты и поля выдачи сверены с исходной
`merchantBuy`. Сервер принимает только товар, количество, ожидаемую версию
и ID запроса; цена, баланс, награды и копия сохранения от клиента игнорируются.
Запись выполняет исходный `saveGameState`: история, профиль и CAS версии.
После покупки Godot заново получает магазин и полный общий сейв для меню/HUD.

Текущий Telegram интерфейс торговца пока использует свою прежнюю функцию
`merchantBuy` и сохранение. Новый Telegram endpoint подготовлен и проверен,
но переключение интерфейса на него требует отдельного изменения и проверки
очереди сохранений. Оно не включено этим этапом.

**Повторы:** `ppa_native_commands` хранит владельца, requestId, хеш и текст
команды, результат. Повтор того же ID возвращает прежний ответ, а не выполняет
покупку/распределение очков ещё раз. Godot атомарно сохраняет только запрос
и случайный ID до отправки; пароли, bearer и копия инвентаря не сохраняются.
Ответ сверяется с аккаунтом, игрой, контрактом и ID. После подтверждения
читается свежее состояние, старый ответ повторного запроса не показывается
как текущее. Смена аккаунта не переносит команду на другого персонажа.

Если Worker прервался внутри существующего многошагового кланового действия,
команда остаётся pending. Автоматического снятия блокировки по времени нет:
часть действия могла уже выполниться. Перед разблокировкой оператор сверяет
command_json и общие таблицы. Нужен отдельный процесс такого восстановления
до широкого включения команд; повреждённая локальная запись также блокирует
новое действие вместо повторного списания с новым ID.

## Флаги новых функций

| Флаг | Действие |
|---|---|
| `PPA_GODOT_CLAN_READ_ENABLED=1` | Подписанное чтение общего клана |
| `PPA_GODOT_CLAN_ACTIONS_ENABLED=1` | Перечисленные 10 команд клана |
| `PPA_MERCHANT_READ_ENABLED=1` | Общий каталог, баланс, остатки и версия |
| `PPA_MERCHANT_ACTIONS_ENABLED=1` | Серверная покупка 12 товаров |

По умолчанию новые маршруты возвращают 404. Исходные native флаги чтения
сохранения/города/NPC описаны в `shared-world-next-steps-20261010.md`.

| Торговец | Каталог, выбор количества, подтверждённая серверная покупка | Переключение Telegram UI на typed endpoint; проверка на двух клиентах |

| Склады | Чтение личного/кланового/премиум склада и виртуальные 200/500/50 слотов | Перенос по серверному UID, ёмкости, права, CAS и отсутствие дублей |

| Данжи / PvE | Исходные карты и offline визуальные сущности | Назначение общей комнаты, исходные mob ID, authority snapshots, hit/control, смерть/респавн/награды |

Часть текущей Telegram экономики выполняется в клиентском JavaScript, а
некоторые старые серверные операции используют несколько неатомарных записей.
Одно чтение `/api/game/state` не делает эти операции доступными в Godot.
Дальнейшие адаптеры требуют извлечения действующих правил и проверки
транзакций. Создавать вторую копию инвентаря или доверять присланному предмету
для native покупки/склада/аукциона нельзя.

## Подтверждённые проверки и порядок выпуска

- Реальные SQLite таблицы + исходные клановые обработчики: роли, делегированные
  права в Telegram/Godot, один общий клан, отсутствие изменения сейва,
  повтор команды, повтор бонуса, чужой аккаунт, отключённые флаги,
  24 часа после выхода в обоих направлениях и восстановление после срока.
- Торговец: 192 сравнения с checksum-locked исходной функцией; реальные
  Worker load/save, история, CAS, конфликт во время записи, HMAC Telegram,
  сохранение HP/MP/экипировки/прогресса и чужого сейва.
- Godot 4.6: правильный контракт/владелец, запрос после перезапуска,
  неподтверждённая покупка, права, native кнопки/передача действий,
  цена из ответа сервера, вещи клана из общей таблицы, очистка при смене
  аккаунта. Предыдущие меню/readonly мосты и городской протокол проверяются
  отдельно.
- Серверные файлы и обработчики PvE/PK/Arena не изменены этим этапом.
  HUD по-прежнему не выполняет живые атаки или расход боевых зелий.

Порядок: интегрировать ticket/read-only/городские зависимости; проверить новые
PR; завершать оставшиеся typed NPC операции; подключать общий PvE, затем
PK/Arena с прежними формулами/моментом урона. Выпуск требует серверной версии
и APK из согласованных веток, проверки Telegram до/после включения флагов,
двух разных аккаунтов в обоих направлениях, восстановления после обрыва,
проверок дублей и FPS на целевом Android устройстве. Готовые unit/headless
проверки не заменяют двухклиентный бой или замер времени кадра.
