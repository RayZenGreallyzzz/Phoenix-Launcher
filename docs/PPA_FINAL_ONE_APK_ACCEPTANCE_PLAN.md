# PPA — одна финальная установка после подготовки всех систем

**Статус: рабочая контрольная точка, не разрешение на выпуск.**
Владелец проекта решил **не скачивать/устанавливать APK после каждого патча**.
Надо завершить разработку в черновых ветках, делать CI на каждом изменении,
подготовить безопасный staging, затем согласовать один полный тестовый цикл.
**Нет разрешения на деплой, слияние PR, правку production D1 или включение флагов.**

## Единственный источник правды

Telegram PPA + Godot PPA = одна игра на одной канонической серверной логике.
Подлинные аккаунты, сейвы D1, Gold/PPA/Gram, руны, книги, вещи с UID и
заточкой +7, кланы и аукцион — без отдельного Godot кошелька или дублирования.
Оригинальная комиссия аукциона **10%** неизменна.

Серверный черновик: RayZenGreallyzzz/ppa-phoenixpixarena PR #34
(`feature/ppa-shared-forge-material-view-20261010`).
Godot-черновик: RayZenGreallyzzz/Phoenix-Launcher PR #33
(`feature/godot-shared-forge-material-view-20261010`).
Это зависимые stacked-ветки. Перед каждым изменением сверять актуальный HEAD.

## Что подтверждено и что ещё НЕ доказано

| Контур | Готовность к единой установке |
| --- | --- |
| Godot город, 3D визуал, элементы меню, инвентарь, иконки | Реализовано частично, headless CI и тесты на планшете были; FPS и все классы потребуют финальной проверки |
| Версионированное чтение исходного D1 сейва и 30-секундный RAM кеш | Есть; ручной refresh/серверные команды должны всегда проверяться |
| NPC витрины, кузница, личный склад, Black Market | Чтение реальных данных и справочные разделы есть; флаги серверных действий по умолчанию OFF |
| Кланы, клановый склад, аукцион, 10% комиссия | Серверные контракты и тесты есть в PR, **реальная интеграция двух клиентов не доказана** |
| Seller credits Telegram ↔ Godot | Нужна отдельная совместимость со старыми закешированными Telegram-клиентами и D1 backup; без неё payouts запрещены |
| Один realtime мир: другие игроки, перемещение | Частично; необходимо подтвердить общие серверные координаты, видимость и гонки двух клиентов |
| Полный PvE, ПК, данж, боссы, лут | В Godot остаются локальные превью/недовключённые функции; запрещено выдавать их за реальный общий бой |
| Арена и клановые войны | Частичный UI/тренировка; реальные сетевые бои и награды ещё требуют серверной проверки |
| Запуск через Telegram/launcher и единая идентичность | Частично; недопустимо переименовать/создать второго персонажа или потерять сейв |
| Android билд/подпись и адаптация телефона | GitHub собирает APK; финальная установка должна проверить package ID `com.phoenixgames.ppa`, прежний сертификат и реальный FPS |

## Правило до финального теста

- Не выдавать пользователю очередную APK после каждого исправления.
  CI может собирать внутренние артефакты, но пользователь загружает только
  согласованный **финальный QA-кандидат**.
- Для каждого модуля: отдельный минимальный патч → headless CI →
  тест конфликтов с прежним PPA → проверка сохранения/экономики.
  Зелёный тест НЕ означает, что функция полностью реализована в live.
- Никаких автоматических экономических действий в локальном Godot.
  Состояние, цена, версия сейва и список разрешений — только от сервера.
- Серверное чтение сначала проверить на **изолированной staging D1**,
  с двумя игроками, без реальных аккаунтов/валют и с закрытыми POST-действиями.
  Любой live Worker deploy, включение флагов или перенос D1 требует
  отдельного явного решения владельца.
- До интеграции аукциона: старые Telegram лоты не продавать из Godot
  без проверенного escrow; legacy seller payout не активировать дважды.

## Последовательность финальной проверки

1. Предварительные offline/CI тесты всех модулей, тесты двум пользователям,
   смены bearer и аккаунта, 100 ячеек сумки, +7, денег/предметов, кланов и торгов.
2. Утверждённый isolated staging: два параллельных тестовых клиента,
   сверка Telegram и Godot через один D1, read gates сначала, write gates отдельно.
3. Решение о выпуске тестового окружения и одна собранная **подписанная APK**;
   установка ПОВЕРХ прежней, без удаления пользовательских данных.
4. На планшете: запуск, FPS, движение, NPC все вкладки, сумка/склад/экипировка,
   3D персонажи, книги/руны/навыки, Black Market, кланы, PvE, боссы, арена.
   Телефон проверяется отдельно, планшетную раскладку не ломать.
5. На двух клиентах одновременно: разные игроки видят одни и те же мобы,
   HP, позицию/анимацию и результат реального боя; одни валюты, кланы,
   аукционные лоты, изменения предметов, лут и награды.
6. Только после успешного сравнения и явного решения — обсуждать production
   rollout с бэкапом, canary, проверкой старого Telegram WebView и откатом.

**Критерий готовности: не "APK собрана", а "основные игровые сценарии
на обоих клиентах совпадают с одним сервером без потери сохранений".**
